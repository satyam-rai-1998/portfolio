TokenEconomizer helps coding agents stop paying to relearn a repository

By Satyam Rai · November 18, 2026

A coding agent can spend its first few minutes rediscovering which test command works. Start a fresh session tomorrow and the same search can appear on the bill again.

What the researchers measured

On November 16, 2026, Microsoft Research described TokenEconomizer, an open-source project with UC Berkeley and Microsoft Security. The team evaluated 277 bug-fixing tasks across six repositories and five agent–model combinations. It reported average cost reductions of 18.4–30.9% with broadly similar success rates. The researchers included the controller’s own model calls in the cost calculation. Microsoft Research’s methods and results.

Which lessons earn a place in memory?

The controller looks for patterns across completed sessions. Repeated evidence can earn a short repository-specific note a place in the next session’s context. Later evidence can retire it. The controller also trims the tools initially presented to the agent and can intervene when repeated attempts at a task stop making progress. Microsoft Research’s methods and results.

A fair test on your own codebase

Pick a repository with recurring maintenance work and an independent test suite. Compare a sequence of fixes with and without remembered guidance. Keep failed fixes in the denominator. Track cumulative cost as well as cost per accepted fix: the first few sessions have little history to learn from. A revealing test is to change the test command halfway through and see how long the old instruction survives.
