Build an order-support agent

A customer asks, “Has order A100 shipped, and how long do I have to return it?” Start in Copilot Studio or Python, then connect a lookup tool for order status and a document for return policy.

Set up your demo. Use two fictional orders: A100 (Dispatched) and A101 (Processing). Create a text file titled “Demo returns policy” with one rule: customers may return unused items within 14 days of delivery.

Copilot Studio

  1. Create a new agent in a development environment. In its instructions, tell it to answer returns questions from the policy and use the order tool for shipping status.
  2. Upload your demo policy as a knowledge source. Ask whether an unused item is eligible ten days after delivery. Check that the citation opens the right file.
  3. Add an agent flow using “When an agent calls the flow”. Define a text input called order_id. Use a Switch to return Dispatched for A100, Processing for A101 and Unknown order for other IDs. Use “Respond to the agent” to return the status.
  4. Add the flow as a tool and describe when to call it. Test a combined order and policy question in the test pane before publishing to a test channel.

Try it. Ask about A999. The agent should acknowledge the missing order and still answer the policy question.

OpenAI and LangChain

With OpenAI function calling, send the model a description of the lookup function and a schema with one required string, order_id. When the response contains a function call, your application validates the arguments, runs the lookup and sends its result back with the same call ID. The model can then answer using the returned status.

Run it with LangChain and an OpenAI model

Install langchain and langchain-openai in a Python environment. Set OPENAI_API_KEY and OPENAI_MODEL locally using a model that supports tool calling. Run the script below. LangChain handles the calls between the model and your Python function.

import os
from langchain.agents import create_agent
from langchain.tools import tool

@tool
def lookup_order(order_id: str) -> str:
    """Return the status of a fictional order."""
    orders = {"A100": "Dispatched", "A101": "Processing"}
    return orders.get(order_id, "Unknown order")

agent = create_agent(
    "openai:" + os.environ["OPENAI_MODEL"],
    tools=[lookup_order],
    system_prompt="Use lookup_order for order status. Ask for a missing ID.",
)
result = agent.invoke({"messages": [
    {"role": "user", "content": "Has order A100 shipped?"}
]})
print(result["messages"][-1].content)

Check your result. Inspect the messages for a tool response containing “Dispatched”. Then change A100 to A999 and compare the tool result with the final answer.

Azure OpenAI and Microsoft Foundry

Azure OpenAI

Deploy a model with tool-calling support. To use the Responses API, configure the OpenAI client with your Azure endpoint ending in /openai/v1/, provide the deployment name in the model field and authenticate with an authorized Azure credential. Start with an A100 lookup and inspect the function arguments before connecting real data.

Microsoft Foundry Agent Service

Create a prompt agent in your Foundry project, select a deployment and add the order-support instructions. Attach the demo policy using file search where supported. Register the order lookup as a function tool and handle its execution in your application. Assign the runtime identity read access to just the intended data source.

Inspect a run. For A101, check which tool was selected, which ID it received and whether its result was Processing. For a policy question, check the retrieved passage.

Retrieval and RAG

Retrieval-augmented generation (RAG) gives the model relevant passages at answer time. Split the policy by heading, store the document title and version with each chunk, and index those chunks in a service such as Azure AI Search. Retrieve passages the caller can read and pass their text and source IDs to the model.

For “Has A100 shipped, and can I return it?”, call the order tool for the changing shipment status and retrieve the policy for the return window. Cite the policy beside the 14-day answer. If someone asks how long a refund takes, check that the agent says the demo policy does not specify a timeframe.

Tool integration and MCP

Replace the local dictionary with an order API while keeping the lookup signature. Validate the ID and verify the signed-in user owns the order on the server. Return the status and distinguish an unknown order from a service timeout.

With Model Context Protocol, a host connects an MCP client to a server that advertises tools. Expose lookup_order with a required string input, connect a compatible host, inspect its tool list and run the A100 test. Enforce authorization inside the server for every call. This lets multiple clients reuse the same lookup.

Test permissions. Give two fictional users separate orders. Request the other user’s order and check that the tool reveals no status. To add a write action such as cancellation, use a separate tool and confirm the order ID before execution.

Testing and release

  • Known order. A100 should produce Dispatched. Score the status and the policy citation separately.
  • Missing ID. Ask “Where is my order?” and check that the agent requests the ID.
  • Service outage. Simulate a timeout. Confirm the answer explains that status is unavailable and can still answer a policy question.
  • Changed policy. Update the fictional return window to 21 days. Refresh the index and verify that the answer cites the new version.

Record the question, expected facts, tool selected, latency and result. Run the cases again after changing models, instructions or connectors. Start with a test group and inspect failed traces before expanding access.
